# Правила работы в репозитории

Проект **locusfood.by** — сайт натуральных продуктов с доставкой в Витебске.
Стек: Vite + React + TypeScript + shadcn/ui (Tailwind).

## Git: работаем прямо в `main`

Владелец проекта не программист — он проверяет результат глазами на сайте, а не читает
pull request'ы. Поэтому ветки и PR не нужны: **коммитим и пушим прямо в `main`**.

- Перед началом задачи: `git fetch origin && git switch main && git pull --ff-only`.
  Владелец иногда правит код сам через Lovable, а Lovable коммитит в `main` — без
  предварительного `pull` его правки легко потерять или получить конфликт.
- Один коммит — одна задача. Сообщение коммита — по существу, на русском.
- После правки: `git add` нужных файлов → коммит → `git push origin main`.
- **Force-push в `main` запрещён**, историю не переписываем. Конфликт решаем, а не затираем.
- Перед пушем посмотреть `git diff` — не должны уехать `node_modules`, `dist`, `.env`,
  локальные конфиги, `supabase/.temp/`.

Сам пуш безопасен: прод обновляется только командой владельца (см. «Деплой»). Но в `main`
не должно попадать то, что не собирается: битую сборку владелец увидит только в Lovable,
и вместо сайта будет пустое окно.

## Проверки

- Быстрая проверка синтаксиса правленых файлов (памяти почти не требует, работает на хосте
  Hermes): `npx esbuild <файл> --outfile=/tmp/esbuild-check.js`
- `npm run lint` — ESLint по всему проекту.
- Сборка (`vite build`) запускается **на сервере сайта**, не на машине разработки: на хосте
  Hermes мало памяти, сборку легко уронить. Проверка типов (`tsc --noEmit`) здесь тоже падает
  по памяти — гонять её на сервере.
- Dev-сервер локально допустим: `npx vite --host 127.0.0.1 --port 5173`.

## Запреты

- Не заходить в каталоги чужих проектов на сервере: `/var/www/kogti`, `/var/www/beautyopt`,
  `/var/www/femina`, `/var/www/gera`, а также в их nginx-конфиги.
- Не читать секреты и не выводить их содержимое: `~/.ssh`, `~/.hermes`, `auth.json`, `.env`.
- Не удалять файлы без бэкапа.
- Не деплоить в прод без явного подтверждения владельца.

## Деплой

Выполняет владелец — вручную, после того как посмотрит изменения в Lovable. На сервере сайта
команда `update-locusfood` (она же `/var/www/locusfood/deploy.sh`): `git fetch --all --prune` →
`git reset --hard origin/main` → `npm install` → `vite build --outDir dist.new` → подмена `dist`
(предыдущая сборка остаётся в `dist.prev`, откат — оттуда). Агент деплой не запускает.

Lovable синхронизирован с этим репозиторием: коммиты в `main` подтягиваются в проект Lovable,
где владелец проверяет изменения до деплоя.
