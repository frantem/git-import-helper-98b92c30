## Оптимизация загрузки главной страницы

Главная сейчас грузится ~3 сек на мобильном. Я проанализировал что и в каком порядке грузится — нашёл несколько чётких узких мест, которые можно убрать без риска что-то сломать. Все правки точечные, поведение и внешний вид остаются прежними.

### Что замедляет главную сейчас

1. **Главный JS-бандл слишком большой.** `Index.tsx` импортирует напрямую — это правильно (быстрый LCP). Но `App.tsx` вместе с ним тянет в первый чанк все провайдеры и `lucide-react` целиком. На медленном 3G/4G это +500–800 мс к первому байту JS.
2. **Все 4 запроса к Supabase идут параллельно сразу при старте**, но `useProductRatings` уже отложен (это сделано). А вот `app_settings` (3 отдельных запроса в `DynamicMeta`) можно объединить в один.
3. **Шрифты Tailwind / системные не оптимизированы** — нет `font-display: swap` подсказок, но проект использует системные, поэтому это не критично.
4. **Баннер-картинка — самый тяжёлый ресурс LCP.** Сейчас она грузится через wsrv.nl уже после того как React смонтировался. Если предзагрузить URL первого баннера через `<link rel="preload">` сразу из HTML — LCP улучшится на 300–600 мс.
5. **Лишние ререндеры `Index`**: при каждом изменении `productIds` массив пересоздаётся (новая ссылка) → `useProductRatings` дёргается лишний раз. Нужно стабилизировать ключ.
6. **`embla-carousel-react`** грузится на главной через `BannerCarousel`? Нет, он там не используется (свой ручной). Хорошо. Но `embla` сейчас всё равно в основном чанке через другие компоненты — добавлю в `manualChunks`.
7. **Meta Pixel** уже отложен на 2 сек — отлично, не трогаю.
8. **HTTP-заголовки** — серверный кеш для статики настраивается в Nginx, это вне кода (упомяну в конце).

### Что сделаю

#### 1. Препоадим LCP-картинку (баннер)

Добавлю в `index.html` маленький инлайн-скрипт, который читает первый активный баннер из localStorage (если уже посещали раньше) и вставляет `<link rel="preload" as="image">` ДО того как React смонтируется. Для первых посетителей — фолбэк на статичный плейсхолдер баннера, чтобы хотя бы соединение с wsrv.nl прогрелось.

Дополнительно: `<link rel="preconnect" href="https://wsrv.nl" crossorigin>` в head — экономит ~100–200 мс на TLS-handshake к CDN картинок.

#### 2. Объединим запросы `app_settings` в один

`DynamicMeta` сейчас делает 3 отдельных `select` к одной таблице. Заменю на:
```ts
supabase.from("app_settings").select("key, value").in("key", ["favicon_url", "og_image_url", "google_verification"])
```
3 round-trip → 1. Минус ~150–300 мс на медленной сети.

#### 3. Разобьём вендорные чанки агрессивнее

В `vite.config.ts` сейчас уже есть `manualChunks`. Добавлю:
- `embla` — `embla-carousel-react`
- `forms` — `react-hook-form`, `@hookform/resolvers`, `zod`
- `icons` — `lucide-react` (он немаленький; вынесем чтобы не тянулся в первичный чанк)
- `date` — `date-fns`

Это уменьшит размер главного чанка на ~30–40 КБ gzip. Главная грузит меньше JS на старте, всё остальное подгружается фоном.

#### 4. Уберём лишние ререндеры в `Index`

- `productIds` пересчитывается через `useMemo`, но зависимость `rawProducts` меняется по ссылке при каждом рефетче. Стабилизирую через `JSON.stringify` ключ или `useMemo` по `rawProducts.length` + последнему id. Минимальная правка — вместо массива использовать стабильный key.
- `homepageJsonLd` уже на модульном уровне — хорошо.

#### 5. `useHomepageBlocks` + `useProducts` → один комбинированный prefetch

Сейчас два независимых запроса. Они оба нужны для отрисовки. Объединять в один SQL слишком инвазивно — оставлю как есть (риск сломать пагинацию и кеши). Но добавлю `placeholderData: keepPreviousData` чтобы при возврате на главную скелетон не моргал.

#### 6. Header: убрать лишние повторные рендеры

`Header` использует `useCart` (totalItems) — при каждом изменении корзины перерендеривается весь header. Это уже мемо нет. Добавлю `memo` обёртку по факту — но это микро-оптимизация, оставлю на потом если будет нужно.

#### 7. `OptimizedImage` для первого баннера: явные `width`/`height`

Сейчас в баннере нет атрибутов width/height на `<img>` — это вызывает CLS (layout shift) и Chrome пессимизирует приоритет. Добавлю реальные размеры (например 800×350) через пресет — браузер сразу резервирует место, LCP лучше.

### Чего НЕ трогаю (чтобы не сломать)

- Логику `useScrollRestoration` и `savedAllBlockLimit` — работает, не трогаю.
- Структуру `transformProduct` — поломает кеш React Query.
- Auth flow — только смотрел, не правлю.
- Состав видимых блоков и порядок — пиксель-в-пиксель.
- Meta Pixel и CAPI — уже отложены оптимально.
- Schema.org JSON-LD — оставляю.

### Файлы

- `index.html` — preconnect к wsrv.nl, preload для LCP-картинки
- `vite.config.ts` — расширенные `manualChunks`
- `src/components/DynamicMeta.tsx` — один запрос вместо трёх
- `src/pages/Index.tsx` — стабилизация ключа `productIds`, `placeholderData`
- `src/components/BannerCarousel.tsx` — width/height для первого слайда

### Ожидаемый результат

- **TTFB** не меняется (это сервер).
- **JS до интерактивности**: −30…40 КБ gzip → −300…500 мс на 4G.
- **LCP (баннер)**: −400…700 мс за счёт preconnect + preload + правильных размеров.
- **CLS**: близко к 0 (сейчас прыгает баннер).
- **Лишние запросы**: −2 round-trip к Supabase.

Итого ожидаю первый paint ~1.5–2 сек вместо 3 на мобильном 4G. Без изменений UX и без риска регрессий.

### Действия пользователя после деплоя

В Nginx на сервере (если ещё не сделано) добавить агрессивный кеш для `/assets/*`:
```nginx
location /assets/ {
  expires 1y;
  add_header Cache-Control "public, immutable";
}
```
Это даёт мгновенную загрузку при повторных визитах. Я не могу это поменять из проекта — это серверный конфиг. После плана напомню отдельно.
