

## План: Устранить случайное присвоение реферала при посещении профиля продавца

### Проблема
Сейчас **любой** визит на страницу `/seller/:id` записывает `referrer_farmer_id` в localStorage. Это значит, что если покупатель просто кликнул на имя продавца из карточки товара (Product.tsx, строка 728), он автоматически становится «приведённым» этим продавцом. Милена никуда не давала свою ссылку — покупатель просто зашёл на её профиль, и реферал записался.

### Решение
Реферал должен записываться **только при переходе по реферальной ссылке** — с параметром `?ref=1` в URL. Ссылка, которую продавец копирует в настройках, уже содержит slug. Нужно добавить `?ref=1` к копируемой ссылке и проверять этот параметр при записи реферала.

### Изменения

**1. `src/pages/SellerProfile.tsx`**
- Записывать `referrer_farmer_id` в localStorage **только** если в URL есть параметр `?ref=1` (или `ref=true`)
- Обычные переходы из карточки товара (без `?ref`) не будут создавать атрибуцию

```typescript
// Вместо безусловной записи:
// localStorage.setItem("referrer_farmer_id", farmerData.id);

// Проверяем наличие ref-параметра:
const searchParams = new URLSearchParams(window.location.search);
if (searchParams.get("ref")) {
  localStorage.setItem("referrer_farmer_id", farmerData.id);
  localStorage.setItem("referrer_farmer_ts", Date.now().toString());
}
```

**2. `src/pages/seller/SellerSettings.tsx`**
- Добавить `?ref=1` к копируемой ссылке:
```
https://locusfood.by/seller/{slug}?ref=1
```

### Результат
- Обычный просмотр профиля продавца — реферал НЕ записывается
- Переход по реферальной ссылке с `?ref=1` — реферал записывается как и раньше (24ч окно, последний клик)
- Существующие заказы с ошибочным рефералом останутся как есть (можно вручную очистить при необходимости)
