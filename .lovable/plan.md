
# План: новая страница /auth

## Поток для пользователя

### Вход по телефону (по умолчанию)
1. Поле «+375 (XX) XXX-XX-XX».
2. Кнопка «Получить код».
3. На бэкенде проверяем: есть ли профиль с таким номером.
   - **Есть** → отправляем SMS-код → ввод 4 цифр → вход в существующий аккаунт.
   - **Нет** → показываем модальное окно: «Аккаунта с этим номером нет. Зарегистрироваться?» → «Да» → отправляем SMS-код → ввод 4 цифр → создаём новый `auth.users` + строку в `profiles` с `phone`, `phone_verified=true`, пустыми `full_name`/`delivery_address` → автологин. «Нет» → закрываем окно.
4. Пароль для телефонных аккаунтов больше не используется нигде.

### Вход по Email (переключатель сверху)
1. Поля «Email» и «Пароль» → стандартный `signInWithPassword`.
2. Ссылка «Забыли пароль?» → форма с Email → отправляем 4-значный код через Resend → новая форма «Введите код и новый пароль» → проверка кода → `auth.admin.updateUserById` ставит новый пароль → автологин.
3. На этом же экране кнопка «Зарегистрироваться» (email + пароль + подтверждение).

## Что меняется в коде

### Frontend
- **`src/pages/Auth.tsx`** — переписываем. Один tab-переключатель «Телефон / Email». Внутри телефонного таба: 2 шага (номер → код) + модальное окно подтверждения регистрации. Внутри email-таба: 3 режима (вход / регистрация / восстановление пароля по коду).
- **`src/components/PhoneAuthForm.tsx`** — упрощается: только ввод номера, без пароля.
- Удаляем UI, который требовал пароль при телефонном входе.

### Edge Functions
- **`send-otp`** — добавить параметр `mode: "login" | "register"`. Перед отправкой проверять `profiles` по последним 9 цифрам:
  - `mode=login` и профиля нет → вернуть `{ exists: false }` без отправки SMS.
  - `mode=register` и профиль уже есть → вернуть `{ exists: true }` без SMS.
  - Иначе отправлять код и записывать в `phone_otp_codes` с пометкой режима.
- **`verify-otp`** — единственная точка входа по телефону:
  - Если профиль существует → вернуть session для существующего `user_id`.
  - Если профиля нет → создать `auth.users` (`auth.admin.createUser` с virtual email `<digits>@phone.locusfood.by`, случайный пароль), `upsert` в `profiles` (`phone`, `phone_verified=true`, `email=virtual`, `has_password=false`), вставить роль `buyer` в `user_roles`, вернуть session.
  - Возвращаем `access_token` + `refresh_token`; фронт ставит сессию через `supabase.auth.setSession`.
- **`phone-password-login`** — удаляем.
- **`send-email-otp`** уже существует — переиспользуем для сброса пароля. Тема письма «Код для восстановления пароля».
- **`verify-email-otp`** — расширить: принимать `purpose: "password_reset"` и `new_password`. При успехе вызывать `auth.admin.updateUserById(user_id, { password: new_password })`, затем выдавать session.

### База данных
Миграция не требуется — все нужные таблицы (`profiles`, `phone_otp_codes`, `email_otp_codes`, `user_roles`) уже есть.

## Безопасность
- Rate-limit на `send-otp` уже есть (`phone_send_log`) — оставляем.
- Email-коды храним с TTL 15 минут, max 5 попыток ввода.
- Сервисный ключ используется только внутри edge-функций.

## Проверка после внедрения
1. Новый номер: «Получить код» → модалка «Зарегистрироваться?» → код → попадаем на главную, в `/settings` номер уже заполнен.
2. Существующий телефонный номер: «Получить код» → код → вход.
3. Email-вход существующего пользователя.
4. «Забыли пароль» → код в письме → новый пароль → автологин.
5. В корзине «К оформлению» больше не требует Email/пароль — только имя, телефон, адрес (как уже сделано).
