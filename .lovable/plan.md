## Задача

В `/admin/orders` для каждого товара в заказе сейчас можно менять только количество (qty). Нужно добавить возможность также редактировать:

1. **Variant label** (например, «1000» — для веса) — текстовое поле.
2. **Цену за единицу** (`unit_price`, например, 53,00) — поле в рублях с запятой.

Юзкейс: товар на вес. Продавец взвешивает по факту (например, 958 г вместо 1000 г) — админ должен иметь возможность подправить вес и итоговую сумму перед закрытием заказа.  
  
Должны принятые измения отображаться у продавца в заказах и у покупателя. Тесть если я меняю в админ панели любые измения должны подтягивать и на других людей у которых есть этот заказ.

## Что изменится

### `src/pages/admin/AdminOrders.tsx`

1. **State**: рядом с `qtyEdits` добавить:
  - `labelEdits: Record<string, string>` — редактируемый `variant_label`.
  - `priceEdits: Record<string, string>` — редактируемая цена (как строка, чтобы корректно обрабатывать `,` и `.`).
2. **Render** (строки ~643–665): под полем количества добавить ещё два поля:
  - **Вес/вариант** (`Input type="text"`) — биндится к `variant_label`. Подпись «Вес/вариант».
  - **Цена** (`Input` через `parseRublesToKopecks`/`kopecksToRublesString` из `@/lib/priceUtils`) — отображается в рублях с копейками («53,00»), сохраняется в копейки. Подпись «Цена за ед., BYN».
  - Кнопка «Сохранить» появляется, если изменено хотя бы одно из трёх полей (qty / label / price). Сейчас она показывается только при изменении qty — расширить условие.
3. **Хендлер** `handleUpdateItem(orderId, itemId)` (заменит / расширит `handleUpdateQuantity`):
  - Собирает изменённые поля из трёх state-объектов.
  - Валидация: `quantity >= 1`, `unit_price >= 0` (в копейках, целое), `variant_label` — допускается пустая строка → сохраняется `null`.
  - Один `update` в `order_items` с объектом, содержащим только изменённые поля.
  - После — `recalcOrderTotal(orderId)` (уже есть, корректно пересчитает по `unit_price * quantity`).
  - Очищает соответствующие записи из всех трёх edit-state.
  - `fetchOrders()`.
4. **Отображение строки итога товара** (`= 53,00 BYN`, строка 640) остаётся — после сохранения подтянется новое значение из БД.
5. **Иконка/подпись полей**: компактно, в одну/две строки на мобильном (текущий viewport 390px). Использовать `flex-wrap`, `text-xs` для подписей, ширина `w-20`–`w-24` на каждое поле.

## Технические детали

- `unit_price` хранится в **копейках** (integer). Для UI используем уже существующие утилиты:
  - `kopecksToRublesString(item.unit_price)` → начальное значение поля.
  - `parseRublesToKopecks(input)` → значение для сохранения.
- `variant_label` в БД nullable text — пустую строку сохраняем как `null`.
- RLS уже разрешает админу `UPDATE order_items` (политика «Admin can manage order items»). Никаких миграций не требуется.
- Edge functions / уведомления не трогаем — изменение цены не должно триггерить никакие письма.
- `recalcOrderTotal` уже корректно учитывает `delivery_cost` — менять не нужно.

- Структура БД, RLS, edge functions.
