# Индексация в Google: устранение причин из трёх отчётов GSC

## Что показали отчёты (проверено по базе и живому сайту)

**1. «Не найдено (404)» — 145 URL, все `/product/...`**
- 80 URL — старые ссылки по UUID. По базе: 32 из них — живые товары, у которых давно есть slug. Сейчас бот по UUID получает 200 и `canonical` на slug-версию, то есть один товар живёт на двух адресах. Остальные — товары выключенные продавцом (29), удалённые (4) или уже не существующие (15).
- 64 URL — slug-адреса товаров, которые на момент обхода были выключены/удалены. Часть уже снова активна (например `/product/shevr` отвечает 200).
- Итог: 404 сами по себе не ошибка, но старые UUID-адреса надо навсегда склеить со slug-версией через 301, а удалённое отдавать 410, чтобы Google перестал их перепроверять.

**2. «Просканировано, но пока не проиндексировано» — 214 URL** (180 товаров, 21 продавец, 5 категорий `/vitebsk/*`)
- Главная причина найдена в `supabase/functions/prerender/index.ts`: весь текст страницы (H1, описание, характеристики, ссылки) выводится **внутри `<noscript>`**, а в `<div id="root">` пусто. Googlebot исполняет JS и `<noscript>` игнорирует, поэтому «видит» пустую страницу, которая ещё должна догрузить данные из Supabase. Для Google это «тонкая» страница.
- На пререндер-страницах нет внутренних ссылок (только «на главную») — товары и продавцы изолированы друг от друга, ссылочный граф пустой.
- Страницы продавцов: часть доступна и по UUID, и по slug (`/seller/cf86bd56...` и `/seller/to-cake` и т.п.) — дубли.
- В заголовках товаров двойные пробелы («Шевр  от ...»), это мелочь, но выглядит как автогенерация.
- Дополнительно: при замерах главная для Googlebot дважды отвечала ~60 секунд (обычно 0,5 с). В функции нет таймаутов на внутренний `fetch` главной страницы для поиска ассетов — при зависании бот уходит без контента.

**3. «Заблокировано в robots.txt» — 8 URL**
- Актуален только `/catalog?search={search_term_string}` — этот адрес Google берёт из `SearchAction` в JSON-LD главной (`src/pages/Index.tsx` и prerender) и упирается в `Disallow: /*?search=`. Остальные 7 (`?category=`, `?discount=`, `?new=`) — обходы июня по старому robots, сейчас уже не блокируются.

## Что будет сделано

### prerender (основные правки)
1. **Видимый контент вместо `<noscript>`**: H1, описание, характеристики, блок ссылок рендерятся прямо в `<div id="root">`. React (`createRoot`) при загрузке заменит эту разметку своим приложением — для людей ничего не меняется, для бота страница сразу полная.
2. **Внутренние ссылки на каждой странице**:
   - товар → продавец, категория `/vitebsk/<slug>`, до 6 других товаров той же категории;
   - продавец → список его активных товаров;
   - `/vitebsk/<slug>` → товары категории;
   - главная и каталог → все категории + подборка товаров;
   - общий блок навигации: каталог, категории, доставка.
3. **301-редиректы дублей**: `/product/<uuid>` → `/product/<slug>`, `/seller/<uuid>` → `/seller/<slug>` (если slug есть).
4. **Статусы для отсутствующих товаров**: удалённые (`is_deleted`) и несуществующие → **410 Gone**; выключенные продавцом (`is_active=false`) → 200 + `noindex` (совпадает с тем, что видит человек — «товар в архиве»), чтобы при повторном включении страница вернулась в индекс без потерь.
5. **Надёжность**: таймаут 3 с на внутренний `fetch` ассетов с фолбэком, параллельные запросы к базе, `Cache-Control` на ответах, чтобы бот не получал зависших ответов.
6. Убрать двойные пробелы в title/H1 (trim названий товаров и продавцов).
7. Удалить `SearchAction` из JSON-LD главной (в prerender и `src/pages/Index.tsx`) — Google этот блок больше не использует, а он генерирует заблокированный URL.

### Клиентская часть
- `src/pages/SellerProfile.tsx`: при заходе по UUID делать `navigate(slug, {replace:true})` — как уже сделано для товаров.
- `src/pages/Product.tsx`: для товаров в архиве добавлять `<SEO noindex />`, для удалённых — показывать 404.
- `src/pages/Index.tsx`: убрать `SearchAction`.

### Sitemap
- `lastmod` у товаров уже есть; добавить `lastmod` для продавцов и категорий (по `updated_at`), чтобы Google быстрее перекраулил обновлённые страницы после релиза.

## Проверка после релиза
- `curl -A Googlebot` по товару: контент внутри `#root`, ссылки на продавца/категорию/похожие товары, статус 200.
- `/product/<uuid живого товара>` → 301 на slug; `/product/<удалённый>` → 410; `/product/<выключенный>` → 200 + `noindex`.
- `/seller/<uuid со slug>` → 301.
- Главная: JSON-LD без `SearchAction`; 10 последовательных запросов без задержек > 3 с.
- После деплоя (push на сервер + деплой edge-функций) — в GSC нажать «Проверить исправление» по всем трём отчётам и переотправить sitemap.

## Что вне кода (на сервере, по желанию)
- Если 60-секундные ответы повторятся после правок функции — в блоке `@prerender` nginx добавить `proxy_connect_timeout 5s;` и фолбэк `proxy_intercept_errors on; error_page 502 504 = /index.html;`, чтобы при зависании Supabase бот получал хотя бы обычный SPA, а не таймаут.
