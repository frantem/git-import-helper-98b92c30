## Цель

Исправить возврат по кнопке «Назад» из карточки товара так, чтобы главная и каталог открывались ровно на том месте, откуда пользователь перешёл в товар.

## Найденные причины

1. В `Product.tsx` есть отдельный `window.scrollTo(0, 0)` при открытии товара. Он конфликтует с общим менеджером скролла и может записать неправильную позицию предыдущей страницы.
2. Текущий `ScrollManager` сохраняет позицию по `location.key`, но при переходах `PUSH/REPLACE/POP` ключ не всегда является надёжной привязкой именно к странице-списку, особенно если карточка товара делает `replace` со slug URL.
3. Нет явного снимка «я кликнул именно эту карточку товара в этом списке». Поэтому система пытается восстановить абстрактный `scrollY`, а не точку конкретного товара.
4. При возврате список может менять высоту из-за загрузки данных/картинок/блоков, и восстановление по одному `scrollY` всё ещё может попасть не туда.

## План исправления

### 1. Сделать якорное восстановление по карточке товара
- При клике на `ProductCard` сохранить в `sessionStorage`:
  - текущий URL списка (`/`, `/catalog?...`),
  - id товара,
  - текущий `scrollY`,
  - смещение карточки относительно верха экрана.
- Добавить каждой карточке стабильный атрибут `data-product-id`.
- При возврате на список сначала найти эту карточку в DOM и прокрутить так, чтобы она оказалась в том же месте экрана, где была перед переходом.
- Если карточка ещё не отрисовалась, повторять попытку через `ResizeObserver`/`requestAnimationFrame` до появления карточки или до safety-timeout.

### 2. Оставить числовой fallback
- Если карточку найти нельзя, использовать сохранённый `scrollY`.
- Сохранить текущую защиту с временным `minHeight`, чтобы страница не прыгала вверх до загрузки контента.

### 3. Убрать конфликтующий сброс скролла на странице товара
- Удалить или ограничить `window.scrollTo(0, 0)` в `Product.tsx`, чтобы он не портил позицию предыдущей страницы.
- За открытие новой страницы сверху должен отвечать только `ScrollManager` при `PUSH/REPLACE`.

### 4. Улучшить обработку slug redirect
- При `replace` с UUID на slug не перезаписывать позицию списка как новую неправильную позицию.
- Сохранение позиции будет привязано к URL списка и товарному якорю, а не только к `history.key`.

### 5. Проверка результата
- Проверить сценарии:
  - главная → товар → назад;
  - каталог → товар → назад;
  - каталог с фильтром/категорией → товар → назад;
  - товар с UUID, который заменяется на slug → назад.

## Файлы для изменения

- `src/components/ProductCard.tsx` — добавить сохранение якоря карточки перед переходом.
- `src/components/ScrollManager.tsx` — добавить восстановление по товарному якорю + fallback по `scrollY`.
- `src/pages/Product.tsx` — убрать локальный сброс скролла, чтобы не конфликтовать с менеджером.
