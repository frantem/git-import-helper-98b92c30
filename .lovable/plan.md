## Что меняем

Редактируем шаблоны Telegram-сообщений (без изменений бизнес-логики и БД).

Файлы:

- `src/pages/Checkout.tsx` — передать `seller_times` и в `send-new-order-telegram` (нужно для самовывоза).
- `supabase/functions/send-new-order-telegram/index.ts` — переписать тексты под три сценария.

---

## 1. Сообщение покупателю (админу) — курьер

```
Здравствуйте {Имя}! Это locusfood

Мы получили ваш заказ:
- {Товар (вариант)} × {qty} = {сумма} BYN
- {Товар2 ...}
- Курьер {стоимость} BYN
Всего: {итого} BYN

Вы выбрали доставку.
Адрес доставки: {delivery_address}
{estimated_delivery_time}
{Карта./Наличные.}

Подскажите:
1. Всё верно?
2. С какой суммы нужна будет сдача?   ← только при cash
```

## 2. Сообщение покупателю (админу) — самовывоз (self)

Группируем позиции по продавцу, для каждого блок:

```
Здравствуйте {Имя}! Это locusfood

Мы получили ваш заказ!
Вы выбрали самовывоз:

{Имя продавца}
{Адрес продавца: city, street, address_details}
{Время самовывоза этого продавца}
- {Товар (вариант)} × {qty} = {сумма} BYN
- {Товар2 ...}

{Следующий продавец — тот же блок}

Всего: {итого} BYN

{Карта./Наличные.}

Подскажите:
1. Всё верно?
2. С какой суммы нужна будет сдача?   ← только при cash
```

Адрес продавца берём из таблицы `farmers` (`city`, `street`, `address_details`), время — из `seller_times[farmer_id]`, который Checkout уже считает и передаёт в `send-self-pickup-notification`. Расширим вызов `send-new-order-telegram` тем же объектом и в edge-функции примем поле `seller_times` (опционально).

## 3. Сообщение покупателю (админу) — pickup (ПВЗ)

Оставляем текущую структуру, но строка способа доставки = `Вы выбрали самовывоз из «{pickup_point.name}».` + строка `estimated_delivery_time` + оплата. (Без изменений по сути, кроме унификации.)

## 4. Сообщение продавцу

Меняем строку способа доставки на короткое слово вместо «Вы выбрали…»:

- courier → `Курьер`
- pickup  → `Самовывоз из ПВЗ`
- self    → `Самовывоз у продавца`

Дальше — строка времени (для self берём `seller_times[farmer_id]`, не общий `estimated_delivery_time`), пустая строка, «Пожалуйста, подтвердите заказ» + кнопка «✅ Подтверждаю» (как сейчас).

Пример (courier):

```
Новый заказ!
- Бенто торт (500 г) = 50,00 BYN

Курьер
Завтра 22:00–23:00

Пожалуйста, подтвердите заказ
```

Пример (self, у этого продавца время 16:00–16:30 завтра):

```
Новый заказ!
- Трайфлы (1300 гр) = 55,00 BYN

Самовывоз у продавца
Завтра 16:00–16:30

Пожалуйста, подтвердите заказ
```

## Технические детали

1. `Checkout.tsx`: в вызов `supabase.functions.invoke("send-new-order-telegram", { body: { orderId, seller_times: sellerTimesMap } })` добавить `seller_times` (всегда передаём, для не-self будет пустой объект — безопасно).
2. `send-new-order-telegram/index.ts`:
  - Принимаем `{ orderId, seller_times?: Record<string,string> }`.
  - Дополнительно тянем `farmers.city, street, address_details` (уже выбираем farmers — добавим поля).
  - Хелпер `formatFarmerAddress(f)` = `[city, street, address_details].filter(Boolean).join(", ")`.
  - Хелпер `itemLine` оставляем (минус префикс `-`  уже есть).
  - Ветка адмінского сообщения:
    - `delivery_type === "courier"`: текущий формат + новая строка `Адрес доставки: {order.delivery_address}` сразу под `Вы выбрали доставку.`
    - `delivery_type === "pickup"`: как сейчас.
    - `delivery_type === "self"`: новый формат с группировкой по продавцу. Не выводим общий `estimated_delivery_time`. Линия «Курьер … BYN» не выводится. В конце — `Всего:` и способ оплаты.
  - Ветка продавцу: заменить `deliveryHeader` на короткое слово; для self использовать `seller_times[farmerId]` вместо общего dateTimeLine.
3. Никаких миграций БД, никаких новых секретов. RLS не трогаем.

## Чего НЕ делаем

- Не меняем email-уведомления (`send-new-order-notification`, `send-self-pickup-notification`).
- Не меняем `AdminOrders`, `SellerOrders`, корзину, чекаут-UI.
- Не меняем callback подтверждения заказа продавцом.
