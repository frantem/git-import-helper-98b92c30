## Что подтвердилось

- В живом `sitemap.xml` сейчас 305 URL, но первые товарные URL из sitemap отдают `404` для Googlebot.
- Причина этих 404 подтверждена в коде: `prerender` ищет у товара поле `category`, которого нет в таблице `products`. Из-за ошибки запроса товары из sitemap становятся ложными 404 для ботов.
- `sitemap` сейчас ставит `<lastmod>` равным текущей дате для главной, каталога и категорий. Это не страничная дата изменения, поэтому Google получает шумный сигнал о ежедневном изменении страниц.
- В базе сейчас 256 активных товаров, 35 незаблокированных продавцов и 12 категорий для посадочных `/vitebsk/...`.

## План исправления

1. Исправить `supabase/functions/prerender/index.ts`
   - Убрать запрос несуществующего поля `products.category`.
   - Получать категорию через существующую связь `category_id -> categories(name)`.
   - Сохранять поведение: активные товары отдают `200`, удалённые/неактивные — `404 + noindex`.

2. Исправить `supabase/functions/sitemap/index.ts`
   - Убрать `<lastmod>` там, где он генерируется от текущей даты или fallback-даты.
   - Оставить `<lastmod>` только у товаров, где есть реальный `products.updated_at`.
   - Добавить в sitemap статические публичные страницы, которые уже есть в приложении: `/delivery`, `/privacy-policy`, `/oferta`, `/seller-terms`, `/cookies`.
   - Корректно кодировать slug в URL, чтобы пробелы/кириллица/спецсимволы не создавали проблемные URL.

3. Проверить live-ответы после деплоя Edge Functions
   - Задеплоить функции `prerender` и `sitemap`.
   - Проверить несколько URL из sitemap как Googlebot: товары должны возвращать `200`, удалённые страницы — `404 + noindex`.
   - Проверить, что sitemap больше не содержит текущую дату как массовый fallback-lastmod.

4. SEO-панель
   - Текущие встроенные SEO findings устарели, поэтому не буду отмечать их исправленными без свежей проверки.
   - После правок запущу свежий SEO scan, чтобы вкладка SEO переоценила состояние проекта.

## Важно

Это устраняет техническую причину массовых ложных 404 и улучшает качество sitemap. Уже попавшие в Google Search Console URL обновятся не мгновенно: после публикации/деплоя нужно отправить sitemap заново или запросить переобход важных URL в Search Console.
