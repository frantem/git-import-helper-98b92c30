## Цель
В `/admin/orders` визуально отображать факт подтверждения товара продавцом (сейчас видно только «собран» ✓ либо пустой кружок ○ — подтверждение никак не отражается).

## Текущее состояние
В `src/pages/admin/AdminOrders.tsx` для каждого `order_items` рендерится индикатор:
```
{item.status === "collected" ? "✓" : "○"}
```
Поле `confirmed_at` у позиции не запрашивается и не используется, хотя в БД оно заполняется через RPC `confirm_order_items_for_farmer` при нажатии продавцом «Подтвердить заказ».

## Что меняем

### 1. `src/pages/admin/AdminOrders.tsx`
- В `interface OrderItem` добавить `confirmed_at: string | null`.
- В `fetchOrders` SELECT для `order_items` добавить поле `confirmed_at`.
- Заменить блок рендера индикатора (≈ строки 708–710) на трёхсостояние:
  - `collected` → зелёная галочка `✓` (как сейчас).
  - не `collected`, но `confirmed_at != null` → закрашенный кружок `●` цветом `text-primary` (акцент `#9ddc09`) + `title="Подтверждён продавцом"`.
  - иначе → пустой `○` `text-muted-foreground` (как сейчас).
- Иконки оставляем текстовыми символами для консистентности с уже принятым стилем в этом файле и в `SellerOrders.tsx`. Размер/выравнивание не меняем.

### Что НЕ трогаем
- БД, RLS, RPC — поле уже пишется.
- `SellerOrders.tsx` — пользователь просил только `/admin/orders`.
- Логика статусов заказа в целом (`pending` → `confirmed` → `delivered`) не меняется.

## Технические детали
- `confirmed_at` доступно RLS-политикой `Admin can manage order items`, дополнительных миграций не нужно.
- Состояние «частично подтверждено» уже видно по разным индикаторам у разных позиций — отдельный бейдж на уровне заказа не добавляем (не было запрошено).
