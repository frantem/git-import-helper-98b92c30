## Проблема

При нажатии «Получить код на Email» появляется «Edge Function returned a non-2xx status code».

Причина: edge-функция `send-email-otp` возвращает HTTP 409 (email уже зарегистрирован), 400 (некорректный email), 429 (rate limit), 502 (resend упал). Клиент `supabase.functions.invoke` любой не-2xx статус трактует как сетевую ошибку — поле `data` становится `null`, и мы теряем человеко-читаемое сообщение (`resp?.error`), показывая общий текст вместо «Этот Email уже зарегистрирован».

В текущем кейсе у вас в Supabase уже есть пользователь с этим email (видимо, остался от прошлой попытки регистрации — вы говорили, что удалили из `profiles`, но в `auth.users` он скорее всего ещё есть).

## Что сделать

### 1. `supabase/functions/send-email-otp/index.ts`
Все бизнес-ошибки (валидация email, email уже зарегистрирован, rate limit, ошибка Resend) возвращать с HTTP **200** и телом `{ success: false, error: "...", code: "..." }`. Только настоящие серверные сбои (отсутствие env, ошибка БД) оставить с 500.

Конкретно заменить:
- `400 "Некорректный Email"` → `200 { success:false, error:"Некорректный Email" }`
- `400 "Введите ваш реальный Email"` → `200`
- `409 "Этот Email уже зарегистрирован..."` → `200 { success:false, error:"...", code:"email_taken" }`
- `429 "Подождите минуту..."` → `200 { success:false, error:"...", retry_after: N }`
- `429 "Слишком много попыток..."` → `200`
- `502 "Не удалось отправить письмо"` → `200`

### 2. `supabase/functions/verify-email-otp/index.ts`
Уже возвращает все ошибки с 200 — оставить как есть.

### 3. `src/components/EmailOtpForm.tsx`
Логика чтения `resp?.error` уже корректная, менять не нужно. После фикса edge-функции toast покажет «Этот Email уже зарегистрирован. Войдите или восстановите пароль.» вместо общего текста.

### 4. (Опционально, сообщение для вас)
Зайдите в Supabase Dashboard → Authentication → Users и удалите старого пользователя с тем email, иначе зарегистрировать его повторно не получится. Профиль из `profiles` удалили — а сам auth-аккаунт нет.

## Что НЕ трогаем
- Схему БД, таблицу `email_otp_codes`.
- Логику генерации/проверки кода.
- `verify-email-otp`.
- Frontend (только поведение улучшится автоматически).

## Технические детали

`supabase-js` обёртка `functions.invoke` бросает на любой не-2xx, и тело ответа становится `null` в JS-обёртке у части версий, либо помещается в `error.context` — но в нашем коде мы читаем `data?.error`, поэтому он не виден. Возврат 200 для бизнес-ошибок — стандартный паттерн для функций, вызываемых через `invoke`.
