
План: надёжно сохранить весь экран `/seller/settings` при уходе в другое приложение на мобильном

Проблема
- Сейчас в черновик сохраняется только `settingsForm`.
- Важные части страницы живут отдельно и не попадают в localStorage: `pickupSlots`, `maxOrdersPerDay`, `busyDates`, `vacationDates`.
- Поэтому после сворачивания браузера/переключения на другое приложение часть введённых данных пропадает.
- Плюс используется общий ключ `seller_settings_draft`, из-за чего на одном устройстве могут смешиваться черновики разных продавцов.

Что изменю
1. `src/pages/seller/SellerSettings.tsx`
   - Уберу для этой страницы текущую привязку `useDraftState("seller_settings_draft", ...)`.
   - Добавлю отдельный черновик именно для настроек продавца с ключом вида `seller_settings_draft_${user.id}`.
   - Буду сохранять в localStorage не только текстовые поля, а весь набор данных страницы:
     - `settingsForm`
     - `pickupSlots`
     - `maxOrdersPerDay`
     - `busyDates`
     - `vacationDates`
   - При открытии страницы сначала загружу данные из БД, затем поверх них восстановлю черновик текущего пользователя, если он есть.
   - Черновик не буду очищать при загрузке страницы, чтобы несохранённые правки не терялись.
   - После успешного сохранения очищу только черновик текущего пользователя.

2. Корректная сериализация дат
   - `busyDates` и `vacationDates` буду сохранять как строки дат.
   - При восстановлении превращу их обратно в `Date[]`, чтобы календарь продолжал работать без поломок.

Почему так
- Оставлять старый общий `useDraftState` здесь недостаточно: он покрывает только часть формы, а эта страница содержит составное состояние с календарями и графиком.
- Делать очистку черновика при загрузке нельзя, иначе мобильный сценарий снова сломается.

Технически
```text
DB данные продавца
  -> собрать полный state страницы
  -> проверить localStorage по ключу текущего user.id
  -> если есть черновик, аккуратно наложить его поверх данных из БД
  -> отрисовать страницу

Любое изменение / pagehide / visibilitychange
  -> сохранить полный snapshot страницы в localStorage

Успешный Save в Supabase
  -> удалить только seller_settings_draft_${user.id}
```

Результат
- В `/seller/settings` после переключения на другое приложение и возврата обратно останутся:
  - название
  - описание
  - район/населённый пункт
  - slug
  - адрес самовывоза
  - график работы
  - лимит заказов
  - занятые даты
  - отпуск
- Черновики разных продавцов больше не будут путаться между собой на одном устройстве.
