# Вкладка «Клиенты» в панели продавца

Новый раздел, который автоматически собирает список клиентов из заказов продавца — без отдельной таблицы и ручного ввода.

## Что появится

Новая карточка «Клиенты» в панели продавца (рядом с «Мои товары», «Заказы», «Моя страница», «Настройки») и страница `/seller/clients`.

### Данные по каждому клиенту

Считаются на лету от текущей даты (Минск), группировка по покупателю:

- Имя и телефон (телефон — кликабельная `tel:` ссылка)
- Всего заказов
- Дата последнего заказа
- Статус

### Логика статуса (первое совпадение)

1. Дней с последнего заказа > 60 → «Пропавший» (красный бейдж)
2. Иначе заказов = 1 → «Новый» (голубой бейдж)
3. Иначе → «Постоянный» (зелёный бейдж)

### Интерфейс

- Сверху фильтр-переключатель: Все / Новые / Постоянные / Пропавшие — с количеством в каждой категории, напр. «Пропавшие (4)».
- Список: имя + бейдж статуса, телефон-ссылка, мелким текстом «N заказов · последний 12.08.2026».
- Сортировка: по умолчанию от новых заказов к старым. В фильтре «Пропавшие» — от самых давних к недавним (самые срочные сверху).
- Пустое состояние: «Пока нет клиентов» / «В этой категории никого нет».

## Техническая часть

- Новый файл `src/pages/seller/SellerClients.tsx`, lazy-роут `/seller/clients` в `src/App.tsx`, ссылка-карточка в `src/pages/SellerDashboard.tsx`.
- Доступ как у других разделов продавца: `role === "seller" | "admin"`, иначе редирект; farmer_id ищется по `farmers.user_id = auth.uid()`.
- Загрузка данных повторяет паттерн `SellerOrders.tsx`:
  1. `order_items` по `farmer_id` с вложенным `order:orders(id, created_at, status, buyer_id)`;
  2. уникальные `buyer_id` → RPC `get_buyer_profiles_for_seller` для имени и телефона;
  3. агрегация в память: по `buyer_id` — количество уникальных заказов и максимальная `created_at`. Отменённые заказы (`status = 'cancelled'`) в подсчёт не идут.
- Изменений в базе, RLS и edge-функциях не требуется — существующая RPC и политики уже дают продавцу доступ к нужным полям покупателей.
- Формат даты — через существующие утилиты (Минск), стили — только семантические токены и уже используемые классы бейджей.
